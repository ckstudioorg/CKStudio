# CK Studio website — notes for Claude

Website for **CK Studio (Chenna Keshav Studio)**, a pre- and post-production / AI ad-film studio in Hyderabad (IDA Jeedimetla). Live at https://ckstudio.org, hosted on GitHub Pages from the repo `ckstudioorg/CKStudio`.

The owner is **not a developer**. Explain everything in plain, non-technical language.

## Standing rules (always follow)

1. **Never touch the `CNAME` file.** It holds the custom domain (`ckstudio.org`). Don't edit, move, rename, or delete it.
2. **Before making changes:** run `git pull`, then create a new branch named after the task (e.g. `update-contact-phone`). Never work directly on `main`.
3. **Keep it a static site that works on GitHub Pages.** Don't add anything that needs a server, database, or a *new* build step/tool without asking first. (The existing React + Vite build that GitHub Actions runs is already in place — keep using it, but don't add to it without asking.)
4. **Small steps, plain-language explanations.** After each change, say what changed in words a non-developer understands (what they'll see on the site, not code details).
5. **Don't commit or push until the owner has previewed the change and said OK.** Show the change in a local preview first (`npm run dev` → http://127.0.0.1:3000/).
6. **When approved:** commit with a clear message, then explain how to merge into `main` so the live site updates (push the branch, open a pull request on GitHub, click Merge). Merging to `main` deploys automatically in a few minutes.
7. **Keep the design consistent** with the existing look (the 2026 luxury "premiere night" design described below) unless a redesign is requested.

## How the site is built

A **React single-page app** (TypeScript + Vite 8 + Tailwind CSS 4, GSAP + Lenis + Motion for animation). The source in `src/` is turned into the real website in `dist/` by a build step.

- **Deploying:** `.github/workflows/deploy.yml` runs on every push to `main`: installs packages, runs `npm run check` (type check + tests + build), and publishes `dist/` to GitHub Pages. If the check fails, the live site is not updated (the old version stays up).
- **Checks on branches:** `.github/workflows/check.yml` runs the same check on other branches and pull requests, without deploying.
- **Run locally:** `npm ci` once, then `npm run dev` (http://127.0.0.1:3000/). `npm run check` runs everything the deploy runs. Project asks for Node 24 (`.nvmrc`); this PC has Node 25 — it works, but may print an "engine" warning.
- **Custom domain:** `CNAME` sits in the repo root (not in `public/`), so it isn't copied into `dist/`. With GitHub Actions deploys, the domain is held in the repo's Pages settings, so this is fine. Leave it alone either way.
- **Ready-made pages (pre-rendering, for Google):** `npm run build` also runs `npm run prerender`: `src/entry-server.tsx` renders every page at build time and `scripts/prerender.mjs` saves it as real HTML (`dist/index.html`, `dist/blog/index.html`, `dist/blog/<slug>/index.html`, `dist/faq/index.html`, `dist/services/<slug>/index.html`, `dist/privacy/index.html`, `dist/terms/index.html`, `dist/404.html`) with the full text, title, description, link-preview tags and structured data, plus `dist/sitemap.xml`. The ready-made page is **visible straight away**; `src/main.tsx` then attaches the live site to it (`hydrateRoot`, "hydration"). So the first render in the browser must match the build exactly: no `window`/`matchMedia`/dates in render or `useState` initialisers (decide in an effect instead, like `Hero` `reduced` and `CustomCursor`), same component tree on server and client (`App.tsx`), `AnimatePresence initial={false}` for the first page, Header `initial={false}`. Entrance animations skip elements that arrived ready-made and are already on screen (`alreadyOnScreen` in `lib/prerendered.ts`, used by `revealLines`/`riseIn` and the BlogPost cover / 404) so nothing flickers. The hero **opening** (logo assembling) is plain CSS keyframes in `foundation.css` ("Hero opening") so it starts before any code loads; GSAP only runs the scroll curtain on the outer wrappers. Until GSAP takes over (`data-js` on `[data-hero-stage]`), CSS holds the hero content hidden; the home page HTML starts with `--ck-header-logo:0`. Hydration problems are logged as `[hydration]` warnings in the console. Each page preloads its own code file (`modulepreload`, from the Vite manifest). Speed on a simulated slow 4G (2026-10-21): first content ~1.0 s (was 2.5–3.5 s). Page addresses end in `/` (`/blog/`, `/faq/`, `/blog/<slug>/`); GitHub Pages redirects `/blog` → `/blog/`. Code that runs during render must not touch `window`/`document` (guard with `typeof window`), or the build fails. The build fails if a page has no `<h1>`.
- **Search details:** titles under ~60 characters (long article titles get a shorter search title in `articleSearchTitles`, `content/seo.ts`; " | CK Studio" is added only when it fits), article descriptions are trimmed to ~158 characters automatically; `robots.txt` explicitly welcomes AI crawlers; `<html lang="en-IN">` (the prerender script matches that exact tag). One source, `src/lib/seo.ts` (`getPageMeta`, `headTags`, `sitePaths`, `sitemapXml`); wording in `src/content/seo.ts`; `components/SEO.tsx` swaps the `[data-seo]` head tags on page change (it loads `lib/seo.ts` on demand, so page texts stay out of the main code file; link addresses live in the small `lib/paths.ts`). `index.html` has a `<!--seo-->` marker where they go. Menu/footer items are real `<a href>` links so search engines can follow them — keep them links, not buttons. The old `?/` deep-link restore script in `index.html` is kept for old bookmarks.
- **Build splitting:** `vite.config.ts` puts React and the animation libraries in their own cached files.
- **Blank-page self-recovery:** GitHub Pages lets browsers reuse `index.html` for 10 min (`max-age=600`), so right after a deploy a cached page can point to removed `/assets/` files and render blank. An inline script in `index.html` reloads once (max once per 30 s) if an `/assets/` file fails, a lazy page chunk fails (`vite:preloadError`), or the root element is still empty 8 s after load. Keep it. **Reloads always start at the top:** `lib/smoothScroll.ts` calls `ScrollTrigger.clearScrollMemory('manual')` (App.tsx resets the scroll anyway; setting `history.scrollRestoration` directly gets overwritten by ScrollTrigger). Otherwise the browser jumps back down before the scroll animations are set up, which crashed GSAP in development (React StrictMode runs effects twice; the app went blank) and left the live site at a random spot.

## Design (2026 luxury "premiere night" redesign)

- **Black stage, ivory text, gold details, brand red.** Background `noir` `#0A0807` (`noir-2`/`noir-3` slightly lighter for panels and covers); text `ivory` `#F3EBDC` (`ivory-soft`, `ivory-dim` for quieter text); `gold` `#D4AF37` (`gold-light`, `gold-deep`) for highlighted words, labels, outlines and fine lines; brand red `#8B0000` (`wine`, `wine-bright`, `wine-deep`) for primary buttons, hover washes and velvet glows. Logo: red CK mark with gold "CK STUDIO" (`<Logo tone="lux">`). Owner's choices (2026-10-24): elegant serif headlines, brand red logo with gold accents. Tokens live in `src/styles/foundation.css` (`@theme`); standard Tailwind breakpoints (`sm` 640, `md` 768, `lg` 1024).
- Fonts: **Boska** serif (`font-display`, 400 + 500 with italics) for headlines and big numbers; **Satoshi** (`font-body`) for everything else. Self-hosted in `public/fonts/` (licence in `docs/FONTS.md`), no Google Fonts. Boska 400 is preloaded (only the hero headline uses 500). `.font-display` uses lining numbers site-wide. Sizes: `text-display`, `text-section` (headings beside a list), `text-headline`, plus clamp sizes for giant titles.
- **Building blocks** (`foundation.css`, `@layer components`): `lux-foil` (gold-foil text, usually an italic `<em>` for the highlighted words of a headline), `lux-label` (small gold capitals), `lux-btn` (red lacquer button, gold edge, light sweep), `lux-btn-ghost` (gold outline button), `lux-panel` (dark lacquered card with a gold edge; add an inner `border-gold/10` frame), `lux-foil-v` / `lux-lacquer-text` (gradients for letter-by-letter animations), `lux-form` (dark native pickers, no light autofill boxes), `lux-glow-top` / `lux-glow-bottom` (fade a section's radial glow out before its edge so no line shows where sections meet). Film grain sits on `body::before`. Recurring patterns: roman ivory headline + gold italic highlight; italic serif gold numbers; small gold diamonds (`rotate-45` squares) as bullets and markers; fine gold hairlines (`bg-gold/15–25`) for rules; sharp corners (no rounded cards or pills), circles only for icon buttons; soft red/gold radial glows behind headings.
- Motion: GSAP + ScrollTrigger + SplitText for scroll-scrubbed/pinned animation; Lenis smooth scrolling; Motion for small UI transitions (wrapped in `MotionConfig reducedMotion="user"`). Helpers: `src/lib/smoothScroll.ts` (`scrollToSection`, `resetScroll`, `setScrollLocked`) and `src/lib/motion.ts` (`useGsap`, `revealLines`, `fillWords`, `riseIn`, `countUp`, `drawLine`). `useGsap` only runs animations when the visitor allows motion and cleans up automatically; sections that start off-screen are set up when the browser is idle (fewer long tasks while loading), so a section that pins must pass `{ defer: false }` (Philosophy). SplitText labels only headings for screen readers (`aria` none on paragraphs, which may not carry labels).
- **Gotchas:** never put a CSS `transition` on transform/translate of an element GSAP moves — wrap it in another element. Scope selectors per section (`gsap.utils.selector(root)`); several sections reuse `data-` names. After changing page height (accordions), call `ScrollTrigger.refresh()`.
  - Gradient text (`background-clip: text`, e.g. `lux-foil`) vanishes on words or letters that GSAP moves one by one (SplitText words/chars): add the gradient class to each moving piece in `onSplit` (Contact closing headline, Footer wordmark, NotFound). `revealLines` (whole lines move) is fine with a `lux-foil` `<em>` inside.
  - SplitText lines: a styled span at the very start of the text (e.g. a gold opening quote mark) can be split onto a line of its own — make it `inline-block`. When italic text animates, use line masks (`mask: 'lines'`), not word/char masks, or the leaning letters get clipped.
  - Sticky elements (Services/Process/FAQ headings, Process cards) break inside `overflow-hidden`; keep glows inside the section instead. The page wrappers in `AnimatedRoutes.tsx` are `bg-noir`: a sub-pixel gap between pinned sections shows that colour.
- Section labels ("N° 01 —— ABOUT US", 01 About … 10 Get In Touch) via `components/ui/SectionLabel`. Blog/FAQ filter buttons and search field: `components/ui/Filters.tsx` (a tiny file, so the FAQ page doesn't load the blog text). Missing images use `components/ui/ImageSlot`; article covers without an image use `ArticleCover` (two alternating dark designs). Custom gold cursor only on mouse devices that allow motion.

## Content rules

- **Testimonials:** never invent quotes. Only client-approved ones go in `testimonials.approved` (drafts to send for approval: `docs/TESTIMONIAL_DRAFTS.md`). While empty, the section shows real work.
- **Blog:** 47 real articles: the original 7 in `content/blog.ts` plus 40 SEO/AEO guides (2026-10-21) in `content/articles/` (commercials, ai, production, movies-marketing, video, design, digital, vfx-music-movies). Before adding a guide, check its topic does not overlap an existing one (two pages on one topic compete in Google). The blog text is one code file (~85 KB compressed, blog pages only); if it grows much more, split article bodies per page. Block types: p / h2 / h3 / list / steps / table / tip / quote; inline `[text](/path/)` links and `**bold**` (`components/ui/RichText`). Guides use `answer` (Quick answer box), `keyPoints`, `faqs` (also FAQPage data), `sources` and `service` (links to a service page) — see the writing notes at the top of `blog.ts`. **Never invent statistics, prices, client results or legal facts; cite sources for rules/specs.** Tests check every internal link in articles exists and every guide has an answer, 3+ FAQs and 650+ words. `dist/llms.txt` (summary for AI assistants) and the sitemap are generated at build. Designed number covers until real images (`image:` 1200×800 in `public/images/blog/`).
- **Portfolio:** add a thumbnail with `image:` or a video with `url` + `youtubeId`. `note` is internal and never shown.
- **Hero = logo animation** (storyboard: Claude Design canvas https://claude.ai/artifact/9fqoVuqX95oogiajnWRfgH; the owner later asked for a cleaner opening). On load (no scrolling needed) the full logo assembles centred: C and mirrored K slide together, CK STUDIO rises, PRE | PRODUCTION | POST appear, a gold line draws, the scroll cue arrives. On scroll the logo opens like theatre curtains (C glides off left, K off right, both growing), CK STUDIO sinks back, the tagline fades, and the hero content settles in behind; the small header logo then fades in (`--ck-header-logo` CSS variable on `<html>`). The header stays visible and clear (no white strip) until the hero ends. The owner rejected flying the logo into the header corner ("childish") and giant cropped letters as the opening ("odd"). C and K are vector paths in `components/brand/LogoLetters.tsx` (traced from the official logo); name/tagline pieces in `src/assets/hero/`. Layout numbers in `sections/Hero.tsx` (`LAYOUT`) come from the logo file — re-measure if the logo artwork changes. No hero video any more; one could be added later as an extra layer. **The finished hero must always fit its screen** (it is pinned): the headline and opening logo scale with screen height, and a fit check in `Hero.tsx` (`--hero-fit`, `data-compact`) shrinks the headline slightly, then hides the figures (`data-hero-stats`), then the description (`data-hero-lede`) on very short screens. Buttons never wrap; figures sit beside the buttons from 1000 px wide. Test new hero content at short laptop sizes (e.g. 1366×650, 980×620, 1280×580) as well as phones.
